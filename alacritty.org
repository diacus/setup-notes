#+title: Alacritty Settings
* Load Settings
Since version 0.15 Alacritty reads its configuration from TOML instead of
YAML; loading an =alacritty.yml= file produces a deprecation warning. I have
a template of [[https://gist.github.com/diacus/a0dee144743d69f49f8e540a25549740][alacritty.yml]] at Github Gist still in the legacy YAML format:
download it and migrate it with the built-in =alacritty migrate= command
(see its [[https://github.com/alacritty/alacritty/blob/master/docs/faq.md#how-do-i-migrate-my-config-from-yaml-to-toml][FAQ]]). The gist import line still points to =nord.yaml=, which was
renamed to =nord.toml= in the [[https://github.com/alacritty/alacritty-theme][alacritty-theme]] repository, so fix that in the
migrated file as well.

#+name: alacritty-yaml
: https://gist.githubusercontent.com/diacus/a0dee144743d69f49f8e540a25549740/raw/96d0d132604566610e3241d89d0977c30de9dbee/alacritty.yml

#+begin_src emacs-lisp :results none :var alacritty-yaml-url=alacritty-yaml
  (require 'url)

  (let* ((config-dir (file-name-concat (getenv "HOME") ".config" "alacritty"))
         (yaml-file  (file-name-concat config-dir "alacritty.yml"))
         (toml-file  (file-name-concat config-dir "alacritty.toml")))
    (unless (file-directory-p config-dir)
      (make-directory config-dir t))
    (url-copy-file alacritty-yaml-url yaml-file t)
    (unless (zerop (call-process "alacritty" nil nil nil
                                 "migrate" "-i" "-s" "-c" yaml-file))
      (error "alacritty migrate failed for %s" yaml-file))
    (with-current-buffer (find-file-noselect toml-file)
      (goto-char (point-min))
      (while (search-forward "nord.yaml" nil t)
        (replace-match "nord.toml"))
      (save-buffer)
      (kill-buffer))
    (delete-file yaml-file))
#+end_src

* Install Themes
Themes are distributed as TOML files; follow the instructions at the
[[https://github.com/alacritty/alacritty-theme][alacritty-theme]] repository.

#+name: install-alacritty-themes
#+begin_src emacs-lisp :results none
  (require 'magit)

  (let ((themes-url "https://github.com/alacritty/alacritty-theme")
        (themes-dir (file-name-concat (getenv "HOME") ".config" "alacritty" "themes")))
    (magit-clone-regular themes-url themes-dir nil))
#+end_src

* SSH Term Info
Within an alacritty terminal run the following command.
#+begin_example
infocmp | ssh "$USER@$remote_host" 'tic -x /dev/stdin'
#+end_example

See the [[https://wiki.archlinux.org/title/Alacritty#Terminal_functionality_unavailable_in_remote_shells][Arch Linux wiki]] for details and context.

* Uninstallation

The configuration lives entirely in =~/.config/alacritty=: the migrated
=alacritty.toml= and the cloned =themes= directory, so removing that
directory undoes the setup. As elsewhere in these notes, no shell =rm= is
used: the deletion is done in Emacs Lisp, reporting either outcome to the
=*Messages*= buffer.

#+name: remove-alacritty-config
#+begin_src emacs-lisp :results none
  (let ((config-dir (file-name-concat (getenv "HOME") ".config" "alacritty")))
    (if (not (file-directory-p config-dir))
        (message "Nothing to remove, %s does not exist" config-dir)
      (delete-directory config-dir 'recursive)
      (message "Removed %s" config-dir)))
#+end_src

* Applying the default theme

Unlike kitty, whose themes kitten ships a theme named =Default=, Alacritty's
built-in colors apply as soon as the configuration imports no theme. The
migrated =alacritty.toml= ends in the single-line =import= key under
=[general]=; deleting that line with =replace-match=, in place of a shell
=sed=, and letting the following =alacritty= instance reload is enough.
The remaining empty =[general]= table is valid TOML and harmless.

#+name: apply-alacritty-default-theme
#+begin_src emacs-lisp :results none
  (let ((toml-file (file-name-concat (getenv "HOME") ".config" "alacritty" "alacritty.toml")))
    (if (not (file-exists-p toml-file))
        (message "Nothing to do, %s does not exist" toml-file)
      (with-current-buffer (find-file-noselect toml-file)
        (goto-char (point-min))
        (if (re-search-forward "^[ \t]*import[ \t]*=.*\n?" nil t)
            (progn
              (replace-match "")
              (save-buffer)
              (message "Removed the theme import from %s" toml-file))
          (message "No theme import found in %s" toml-file))
        (kill-buffer))))
#+end_src

Afterwards, running the =Load Settings= block above re-creates the
configuration, importing =nord.toml= again.
