#+TITLE: GNU Emacs settings
* Emacs as daemon in Linux
The service file is stored in [[https://gist.github.com/diacus/359ed1bbaffee1678aad161acf41b39a][Github Gist]] platform. To install it just
run the block below.
#+begin_src emacs-lisp
  (require 'url)

  (let* ((gist-raw-url
          "https://gist.githubusercontent.com/diacus/359ed1bbaffee1678aad161acf41b39a/raw/emacs.service")
         (dest-file (expand-file-name "~/.config/systemd/user/emacs.service"))
         (dest-dir  (file-name-directory dest-file)))
    (unless (file-directory-p dest-dir)
      (make-directory dest-dir t))
    (url-copy-file gist-raw-url dest-file t)
    (message "Systemd emacs service installed in %s directory." dest-file))
#+end_src

After that reload the systemd daemon
#+begin_src shell
  systemctl --user daemon-reload
  systemctl --user enable emacs.service
#+end_src

* Wayland Emacs daemon
The machine runs the native Wayland build (=emacs-pgtk=) on the HiDPI panel;
installing it removes the =emacs-gtk= binary, and both the gist unit above and
the distro unit (=/usr/lib/systemd/user/emacs.service=) hardcode =emacs-gtk=,
so the daemon fails to start with =status=203/EXEC= after the switch.

Fix: a user drop-in that points the daemon at the Wayland build. It survives
package updates, unlike editing the distro file.
#+begin_src conf
  # ~/.config/systemd/user/emacs.service.d/override.conf
  [Service]
  ExecStart=
  ExecStart=/usr/bin/emacs-pgtk --fg-daemon
#+end_src

#+begin_src shell
  systemctl --user daemon-reload
  systemctl --user enable emacs.service
  systemctl --user restart emacs.service
#+end_src

Note: if the gist unit is reinstalled later, =update-alternatives= decides
which build =emacs= resolves to (on this machine: =emacs-pgtk=).
